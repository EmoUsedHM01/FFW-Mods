# No Friendly Fire Script Notes

This folder contains the bytecode patcher for the No Friendly Fire pak mod. Use this file when the game updates and the offsets in `patch_no_friendly_fire.js` need to be remapped.

## Scope

The mod should remain endpoint-only:

- patch `BP_Player.F_ServerDamages` inside `ExecuteUbergraph_BP_Player`
- do not patch spell, projectile, puddle, item, joker, `BP_PlayerState`, `FL_Items`, or `BPFL_FunctionLibrary` assets
- keep the pak list limited to `BP_Player.uasset` and `BP_Player.uexp`
- keep both `ExportBundleData` and generated `ContainerHeader` raw chunks from `retoc to-zen`; dropping the header can leave the game using mismatched base package metadata and freeze the player in lobby

The endpoint damage handler already has branches for player-caused damage. The mod redirects those branches to the existing no-damage path and changes the self-spell comparison operand so self-caused spell damage takes the blocked path too.

## Known Good Edits

The original working mod made these three edits in `BP_Player.ExecuteUbergraph_BP_Player` bytecode:

- `0xfb20`: changed the player-causer comparison operand from `Self` (`0x17`) to `NoObject` (`0x2a`). This is required for self-caused spell damage.
- `0xfb23`: redirected the player pawn causer branch from the damage path `0x5604` to the no-damage path `0x52ff`.
- `0x100c4`: redirected the `BP_PlayerState` spell-causer branch from the damage path `0x5604` to the no-damage path `0x52ff`.

The current June 13, 2026 game version has 222 `BP_Player` exports and remaps the edits to:

- `0xfc15`: `Self` (`0x17`) to `NoObject` (`0x2a`)
- `0xfc18`: `0x501c` to `0x4c94`
- `0x103a2`: `0x501c` to `0x4c94`

The old no-damage target `0x52ff` maps to current target `0x4c94`. Do not use nearby target `0x4dda` as the no-damage target; that is a different continuation/failure path and does not block self-spell damage correctly.

## Updating After A Game Patch

1. Refresh the unpacked game files so `FarFarWest_Unpacked_RetocLegacy\FarFarWest\Content\Player\BP_Player.uasset` is from the new game build.
2. Export `BP_Player` with UAssetGUI. The script currently uses export index `35`; if a future update changes the export order, find the export named `ExecuteUbergraph_BP_Player` and update `exportIndex` in `patch_no_friendly_fire.js`.
3. Remap the three known-good edits in the new `ExecuteUbergraph_BP_Player` bytecode. Keep the same semantics:
   - the player-causer comparison operand must change from `Self` (`0x17`) to `NoObject` (`0x2a`)
   - the player pawn causer damage target must change to the new equivalent of old no-damage target `0x52ff`
   - the `BP_PlayerState` spell-causer damage target must change to that same no-damage target
4. Update these constants in `patch_no_friendly_fire.js`:
   - `prologueDataOffset`
   - `originalPrologue`
   - `branchOpcodeDataOffset`
   - `branchTargetDataOffset`
   - `originalFriendlyFireScriptOffset`
   - `noDamageScriptOffset`
   - `selfComparisonOperandDataOffset`
   - `conditionDataOffset`
   - `expectedConditionBytes`
   - `playerStateCastBranchOpcodeDataOffset`
   - `playerStateCastConditionDataOffset`
   - `playerStateCastSuccessJumpOpcodeDataOffset`
   - `playerStateCastSuccessJumpTargetDataOffset`
   - `playerStateCastFailureScriptOffset`
   - `expectedPlayerStateCastConditionBytes`
5. Rebuild the mod and verify the patched JSON before installing.

The final `.utoc` should list both:

- one `ExportBundleData` chunk for `BP_Player`
- one `ContainerHeader` chunk generated by `retoc to-zen`

## Locating The Player-Causer Patch

The player-causer branch and self-spell operand are adjacent. In the June 13, 2026 build, the relevant unpatched bytecode looks like this around `0xfc05`:

```text
010000003f03000000000000160000001716071c5000000001000000b100000000000000160000001920
```

The important part is:

```text
17 16 07 1c500000
```

Read as:

- `0x17`: `Self` operand; patch this byte to `0x2a`
- `0x16`: comparison opcode
- `0x07`: `JumpIfNot`
- `1c500000`: little-endian branch target `0x501c`; patch this u32 to the no-damage target

## Locating The BP_PlayerState Spell-Causer Patch

The `BP_PlayerState` spell-causer path is a success `Jump` after a `BP_PlayerState` cast check. In the June 13, 2026 build:

- `0x1038b`: `JumpIfNot` opcode for cast failure
- `0x1038c`: cast failure target `0x4dda`
- `0x103a1`: success `Jump` opcode `0x06`
- `0x103a2`: success target `0x501c`; patch this u32 to the no-damage target

When remapping after another update, identify the matching branch structure and no-damage target by bytecode context, not by the nearest-looking return. The target must correspond to the old `0x52ff` path.
